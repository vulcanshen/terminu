# tdp Rules

**Language**: [English](rules.md) · 繁體中文

這裡的每一條都是 **必須遵守**。每條附上「為什麼」，那是它的 origin UX（[Principle P0](README-zh_TW.md#p0-規則服務-ux不是反過來)）。

**偏離**：app 的性質讓某條 rule 不適用時，可以不照做，但要在該 app 的
`docs/dev-remarks.md`「偏離 tdp」一節寫明**哪一條、在哪裡、為什麼**。寫明原因的
偏離是合法的設計決定；沒寫原因的不照做是**違反**，列進 `docs/<app>-terminu-fix.md`。

**引用**：用 `tdp` 加編號，例如 `tdp K4`、`tdp M2`。編號一旦發布就不重排；
廢除的條目保留編號、標記廢除。

## K Core key

### K1 Core key 的意義全 app 不變

| 鍵 | 意義 | 條目 |
|---|---|---|
| `Tab` | focus 移到下一個 surface | K2 |
| `Enter` | 對 focus 項目做最直觀的那個動作 | K3 |
| `Esc` | 取消 / 關閉最上層 | K4 |
| `Space` | 開 / 關 Space menu（當前 focus 能做的事） | K5、M2 |
| `?` | 開 / 關 `?` menu（整個 app 能做的事） | K6、M4 |

表上的鍵在**每一個 surface** 都是這個意義，唯一例外是輸入態（K8）。app 可以不用到
全部（單一 panel 的 app 不需要 `Tab`），也可以另外指定自己的 core key；自訂的
core key 一旦指定，同樣在所有 surface 意義不變。letter hotkey 不能佔用表上的鍵。

**為什麼**：使用者學的單位是**角色**（「取消」「換 focus」「現在能做什麼」），不是
按鍵。角色固定，學一次就在所有 surface、所有家族 app 有效。只要有一個 surface
讓 `Space` 做別的事，使用者就得多學一條「哪裡例外」。

### K2 `Tab` 在當前畫面的 surface 之間輪轉

`Tab` 把 focus 移到當前畫面的下一個 panel，最後一個之後回到第一個。它不跨畫面、
不跨 tab 頁。

**為什麼**：使用者按 `Tab` 期待的是「換一塊」，不是「換一個畫面」。跨畫面的切換
屬於 global operation（M4）。

### K3 `Enter` 做最直觀的動作，由 app 定義

`Enter` 對 focus 項目做**最直觀的那個動作** —— 進目錄、連線、開啟、送出表單。
具體是什麼由 app context 決定，但同一種項目在同一個 app 裡永遠是同一個動作。
在 popup 裡，`Enter` 是接受或送出。

**為什麼**：「確認 / 進入」這種字面定義撐不過真實 app：開檔、連線、送出表單都是
`Enter`，沒有一個字面上是「確認」。使用者對 `Enter` 的期待是「對這個東西做那件
理所當然的事」。

### K4 `Esc` 一次關一層，永不離開 app

`Esc` 取消當前操作或關閉最上層：有 popup 關 popup（包括 toast），沒有 popup 就退出
當前模式（搜尋、選取、拖曳）或往上一層。**一次一層**，而且 **`Esc` 永遠不會離開 app**
—— 到了最上層就什麼都不做。

**為什麼**：使用者迷路時會連按 `Esc` 想回到安全的地方。如果連按的終點是 app 被關掉，
`Esc` 就變成危險鍵，使用者不敢按，也就失去了「取消」這個安全出口。離開 app 是
global operation，有自己的入口（K9、M4）。

### K5 `Space` 開關 Space menu

`Space` 打開 Space menu（M2）；menu 開著時再按一次 `Space` 就關掉它。`Esc` 也能關。

**為什麼**：只能開、不能用同一個鍵關的入口是陷阱 —— 使用者伸手按同一個鍵想退出，
結果沒反應。

### K6 `?` 在任何地方開關 `?` menu

`?` 打開 `?` menu（M4），**在任何 surface 都有效，包括疊在其他 popup 之上**；
再按一次 `?` 關掉，`Esc` 也能關。

**為什麼**：`?` 是「迷路時最後的出口」。如果它在某些 popup 裡按不出來，使用者正好
在最需要它的時候找不到它。

### K7 別名要完整

一個角色綁多個鍵（例如 `Esc` 與 `q` 都做取消）時，別名必須**在所有 surface 同樣有效**。
做不到就不要做別名。

**為什麼**：半套別名（`q` 只在主畫面能取消、popup 裡不行）比沒有別名更糟 —— 它
偽裝成便利，實際上多了一條「哪裡可以、哪裡不行」的規則要學。

### K8 輸入態：熱鍵全部失效

使用者在打字時（表單欄位、input 框、搜尋列），**所有會產生字元的鍵都是字元**，
不觸發任何動作：

| 鍵 | 輸入態下 |
|---|---|
| letter hotkey、`Space`、`?` | 當成字元輸入 |
| `Esc` | 取消輸入（K4） |
| `Enter` | 送出（K3） |
| `Tab`、方向鍵 | 輸入面自己的欄位移動 |

這是 K1 唯一的例外，只在輸入態內有效，離開輸入面立刻恢復。

**為什麼**：`Space` 與 `?` 是可列印字元。不屏蔽的話，使用者打不出含空白的檔名、含
問號的密碼。`Esc` 與 `Enter` 保留，因為它們不跟字元競爭，而且少了它們輸入框就是
出不去的陷阱。

### K9 使用者一定出得去

app 必須提供一個離開的方式，列在 `?` menu 的 global operation 裡。`Ctrl-C` 在
**任何狀態**都能結束 app，包括 popup 開著、正在搜尋、正在打字的時候。唯一例外是
焦點在 PTY 或子程序裡，此時 `Ctrl-C` 屬於那個程序。

**為什麼**：`Ctrl-C` 是所有終端機使用者的肌肉記憶。它在某些狀態下被吞掉，使用者會
以為 app 卡死。

## M Menu 與揭露

### M1 入口要被看得到

非輸入態的每一個畫面都必須**常駐顯示** `Space` 與 `?` 這兩個入口，讓第一次打開
app、沒讀過任何文件的使用者看得到。形式由 app 決定（footer、側欄、空狀態提示）。

**為什麼**：使用者不可能按一個不知道存在的鍵。入口沒被揭露，後面揭露得再完整也
等於不存在（Principle P2）。

### M2 Space menu：item → panel → global 三區

Space menu 列出**當前 focus 能做的所有事**，依作用對象（Principle P3）分區，順序固定：

| 順序 | 區塊標題 | 內容 |
|---|---|---|
| 1 | `item operation` | cursor 指的那一個項目能做的事 |
| 2 | `panel operation` | 當前 panel（或它的 tab）整體能做的事 |
| 3 | `global operation` | 整個 app 的全域動作，與 `?` menu 的 global operation 同一份清單、同一順序 |

- **區塊標題字串固定**，全 app、全家族都用上表的英文原字。
- **沒有對象就沒有那一區**：空清單沒有 item，item operation 連標題一起不出現。
- **只剩一區時不加標題**，直接列出。
- 區塊之間用分隔線隔開。

**為什麼**：使用者從上往下讀，先看到「對我選的這個東西能做什麼」，再看到「對這一整塊」，
最後才是全域。固定的標題字串讓使用者一眼認出「這是同一種 menu」—— 措辭不同的 menu
會被讀成另一**種**選單。global 區放在最後，讓使用者只要記得 `Space` 一個鍵就找得到
所有事，又不會把當前 focus 的動作擠到下面。

### M3 每個動作都要能從 menu 找到

- 當前 focus 的每個 item operation 與 panel operation 都在 Space menu 裡。
- 每個 global operation 都在 `?` menu 與 Space menu 的 global 區裡。
- **letter hotkey 是 menu 裡某一列的捷徑，不是額外的功能**。只能靠熱鍵觸發、menu 裡
  找不到的動作是違反。

判斷一個動作該進哪一區，只看**作用對象**，不看它重不重要（Principle P3）。

**為什麼**：沒看過熱鍵的新使用者只靠 `Space` 與 `?`，就要能在每個 focus 做完所有事。
只要有一個動作要靠事先學，「不看文件就能用」就破了一個洞。

### M4 `?` menu：可執行的 global operation + 按鍵參考

`?` menu 有兩部分：

1. **`global operation` 區**：app 所有全域動作，**可以直接執行**（`j/k` 選、`Enter`
   執行、有熱鍵的列按熱鍵執行）。離開 app 必須在這裡（K9）。
2. **`key reference` 區**：唯讀的按鍵對照，至少列出 app 用到的 core key，其餘（導覽
   鍵、熱鍵）由 app 決定。

**為什麼**：只能讀的說明頁是文件，不是揭露（Principle P2）。全域動作不屬於任何
focus，所以需要一個在任何 surface 都叫得出來、而且能直接執行的地方。

### M5 每一列 = 名稱 + 說明，熱鍵用 `[]` 標出

menu 的每一列左邊是**動作名稱**，右邊是**一句單行說明**：

```
 item operation
 [o]pen                        open it with the OS default app
 [r]ename                                    this item, in place
 ─────────────────────────────────────────────────────────────
 panel operation
 [/] Search                                everything under here
 ─────────────────────────────────────────────────────────────
 global operation
 [q]uit                                            leave the app
```

熱鍵標記規則，全 app 一套（menu、footer、panel hint 都一樣）：

| 情境 | 寫法 |
|---|---|
| 單一字母 | `[r]ename`、`[D]elete` |
| 含 modifier | `[Alt-t]erm` |
| 多字元 | `[go]to` |
| 數字 | 一律放前面：`[3] Favorites`，不嵌進字裡 |
| 沒有熱鍵 | 不加括號 |

- **括號裡印的就是要按的鍵，大小寫算數**：`[A]dd` 是 `Shift+A`。
- 不能只用顏色或 glyph 暗示「這是熱鍵」，要顯式標出來。

**為什麼**：名稱回答「這是什麼動作」，說明回答「它會對什麼做什麼」—— 同一個動詞在
不同 focus 可能意義不同（刪檔案還是取消收藏？）。說明寫不進一行，通常是動作的
命名有問題。數字不嵌進字裡，因為 `432hz` 會被畫成 `4[3]2hz`。

### M6 暫時不能執行的動作：變暗並說明原因

- **對象不存在**：那一列（或那一區）不出現（M2）。
- **對象存在、但現在不能執行**：列照樣出現，**變暗**並寫出原因，cursor 可以停在上面，
  熱鍵不作用。

**為什麼**：藏起來的動作，使用者會以為 app 不支援；變暗加原因，使用者知道「有這件事，
只是現在不行，因為……」。

### M7 入口永遠有回應

`Space` 與 `?` 在任何 surface 按下去都要打開 menu，不能沒反應。沒有可執行的動作時
照樣打開，顯示「沒有可做的事」與關閉方式。

**為什麼**：按下去沒反應，使用者會以為鍵壞了，而不是「這裡沒事可做」。

### M8 其他分組 menu：cursor 相關的放最前

Space menu 以外的 menu 若要分組，第一組是跟當前 cursor 相關的動作，其後每組加上
說明類型的標題。不需要分組時直接列出。

**為什麼**：同 M2 —— 使用者先找「對著我選的東西」。

## L 版面

### L1 窄寬也要能用

在合理的最小尺寸（SSH session 常見的 80×24）下，app 必須仍能完成核心任務。panel
怎麼拆、窄的時候收掉什麼，由 app 決定。

**為什麼**：TUI 的使用場景常常是別人的機器、分割的視窗、手機上的 SSH。要求寬螢幕的
TUI 在最需要它的地方不能用。

### L2 寬度不隨內容浮動

標題、statusbar、chip 等動態文字必須用固定寬度的欄位或 padding，寬度不能跟著內容
長度變。

**為什麼**：寬度一浮動，主畫面跟著左右晃，popup 開關時整個畫面在抖。

### L3 固定列數的 chrome

footer、statusbar、tab 列等常駐列的**列數由 app 決定，一旦決定就鎖死**，不能因為
內容多寡改變。內容放不下就截斷或從尾端捨棄，不折行。

**為什麼**：chrome 多一列，主畫面就少一列，整個 layout 連鎖位移。穩定永遠優先於省空間。

### L4 每一列剛好等於終端機寬度

畫面上的每一列都剛好等於終端機寬度，不多不少，由測試在多種尺寸下守住。

**為什麼**：多一格，終端機就折行，整個畫面錯位；少一格，殘影留在畫面上。CJK 字元與
icon 的寬度估錯是最常見的來源，只有測試抓得到。

### L5 Focus 看得出來，而且不位移

focus 所在的 surface 必須一眼可辨，而切換 focus **不能讓任何內容位移**。

**為什麼**：使用者要知道按鍵會送到哪裡；而 focus 一換畫面就跳，眼睛就得重新定位。

## C 色彩

### C1 最少錨點，其餘推導

先選定少數錨點色（例如：底色、使用者足跡、popup 最上層），其餘層次從錨點推導，
不為每個元素各挑顏色。

**為什麼**：TUI 能編碼層次的只有色相與明度。錨點少，語意才清楚；每個元素各挑顏色，
最後沒有一個顏色有意義。

### C2 明度是 z 軸，不可反轉

從底色到最上層的 popup，明度單向遞進，**越上層越亮**，絕不反轉。

**為什麼**：TUI 沒有陰影與高度，明度是唯一能表達「哪個在上面」的工具。一旦反轉，
使用者就分不出堆疊順序。

### C3 明度帶專職

每個語意佔一條明度帶，其他語意不能用同一條（Principle P4）。

**為什麼**：「使用者足跡」那條帶若也用在 popup 邊框，使用者看到那個顏色會猜「這是我
設定過的東西嗎？」

### C4 警示色不參與 z 軸

錯誤、警告等強訊號色獨立於明度系統，在任何一層都保持同一個顏色。

**為什麼**：警告色若跟著層級變亮變暗，使用者會以為那是該層的普通元素。

### C5 同一個鍵有兩個指示時，標出哪個會觸發

同一個熱鍵在不同 focus 做不同事、而兩個指示**同時看得到**時，用明度差異標出**當前
focus 按下去會觸發哪一個**：會觸發的亮，不會的暗。

**為什麼**：亮度的交接本身就在說「在這裡按這個鍵會做什麼」，不需要文字或 popup 解釋。

### C6 失焦變暗只用於靜態內容

失焦的 panel 若要變暗，只適用於靜態內容；**串流內容（log、即時輸出）失焦時不變暗**。

**為什麼**：變暗的意思是「焦點不在這，晚點再看也行」。串流內容沒有晚點 —— 資訊正在
流過，變暗等於切斷使用者用餘光掃過的路徑。

## P Popup

### P1 每個 popup 只屬於一類

app 定義自己的 popup 分類（例如 menu、confirm、input、viewport、toast、PTY），每類
有固定的版面；**一個 popup 只屬於一類**，不做混血（例如同時是 menu 又是可捲動的 viewport）。

**為什麼**：類別就是使用者對「這個框裡按鍵會怎樣」的預期。混血的 popup 讓同一組鍵在
框裡有兩種可能。

### P2 開關都有動畫，100–200ms

popup 打開與關閉都要有動畫，長度在 100–200ms 之間。

**為什麼**：沒有動畫，使用者感受不到 z 軸變化；太長會打斷節奏。

### P3 邊框色由層數決定

popup 邊框色依它的堆疊層數從錨點推導（C1、C2），不寫死、不反轉。

**為什麼**：邊框色是使用者判斷「這個框在上面」的唯一線索。

### P4 `Esc` 立刻關閉任何 popup

任何看得到的 popup —— 包括會自動消失的 toast —— 按 `Esc` 都要**立即**關閉，不等動畫。
正在關閉中的 popup 不再接收按鍵。

**為什麼**：使用者沒有等倒數的義務。關閉中的 popup 還吃鍵，使用者下一個按鍵就會送錯地方。

### P5 預設保留 source

從 popup A 開出 popup B 時，A 預設留在底下；取消 B 回到 A。

**為什麼**：使用者沒有撤掉 A，只是在 B 上做了一次互動。取消 B 卻連 A 一起不見，
使用者要重新走一遍。（完成 B 之後 A 還要不要留，見 T1。）

### P6 錯誤立刻看得到，但不擋住 app

錯誤必須立刻出現（toast 或 popup），`Esc` 可關，且**不能阻塞 app**。有沒有錯誤歷史
可查由 app 決定。

**為什麼**：看不到的錯誤等於沒發生；擋住 app 的錯誤讓使用者無法處理錯誤本身。

### P7 Confirm：`Enter` 接受、`Esc` 取消，說出後果

- `Enter` 接受，`Esc` 取消（K3、K4）。
- 提示寫出**接受會做的事**（動詞與對象），而不是抽象的 OK。
- 不可逆或破壞性的動作一定要 confirm；可逆的切換不要 confirm。
- confirm 不能被誤觸完成（例如滑鼠點一下不能等於接受）。

**為什麼**：使用者按 `Enter` 前要知道後果；而每一步都 confirm 會讓使用者養成不讀
就按的習慣，真正危險的那一次就沒人看了。

## X Mouse

### X1 Mouse 可有可無

沒有 mouse 也必須能完整操作 app。

**為什麼**：mouse 不是終端機的一等輸入，很多環境（tmux、SSH、螢幕閱讀）根本沒有。

### X2 Mouse 只是鍵盤的對應

有做 mouse 時，每個 mouse 動作都對應到一個鍵盤動作，**不能有只有 mouse 能做的事**。

**為什麼**：mouse 應該是「鍵盤的另一種按法」，不是「另一套要學的東西」。

## T 時間軸

這一章的規則在截圖上看不出來，只存在於使用流程裡（Principle P6）。

### T1 完成 target 之後，source 還有意義嗎？

預設保留 source（P5）。只有在功能上明確判斷「使用者完成 target 之後，source 已經
失去意義」，target 才在進場前清掉 source：

| target | 清掉 source？ | 判斷 |
|---|---|---|
| 短的 confirm / 訊息 | 保留 | 使用者可能想回原 menu 繼續或取消 |
| 長時間的 session（shell、編輯器） | 清掉 | 從 session 出來時注意力已轉移，舊 menu 浮著讓人恍神 |
| 大幅切換 context（drill-down、換頁） | 清掉 | 底下的畫面已經換了，舊 menu 的對象不在了 |

**為什麼**：這個判斷寫不成通則 —— code 裡兩者長得一樣，截圖上也看不出來，只能從
「使用者用完 target 之後，心裡還想不想看 source」推演。

### T2 串流內容失焦不退階

見 C6。這條是「規則服務 UX」（Principle P0）的典型例子：「失焦變暗」的 origin UX
是「不搶焦點」，串流的 UX 是「用餘光看更新」—— 兩個目標剛好落在同一個 panel 上，
規則該擴充，而不是犧牲串流。
